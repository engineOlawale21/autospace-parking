# Autospace documentation

Use this page as the entry point for product and engineering documentation.

| Document | Read it when |
|---|---|
| [Rebuild plan](REBUILD_PLAN.md) | You need the product scope, target domain, admin scope, or phased strategy |
| [Frontend and admin plan](FRONTEND_ADMIN_PLAN.md) | You need screen architecture, feature priorities, or admin parity requirements |
| [Implementation roadmap](IMPLEMENTATION_ROADMAP.md) | You need build order, dependencies, milestones, or release gates |
| [Milestone status](MILESTONE_STATUS.md) | You need the current delivery state, blockers, or next exit gate |
| [Architecture](ARCHITECTURE.md) | You need service ownership, data flow, persistence, or consistency rules |
| [Service catalog](SERVICE_CATALOG.md) | You need microservice responsibilities or invocation dependencies |
| [Development](DEVELOPMENT.md) | You need to run, test, migrate, or troubleshoot the platform |
| [CI/CD](CI_CD.md) | You need merge checks, image publishing, or release guidance |
| [Configuration](CONFIGURATION.md) | You need environment-variable ownership and security guidance |
| [Kafka events](EVENTS.md) | You produce or consume domain events |
| [Contributing](../CONTRIBUTING.md) | You are changing code, migrations, APIs, or documentation |
| [Security](../SECURITY.md) | You found a vulnerability or are changing sensitive functionality |

Documentation must describe current reality separately from target state.
Planned capabilities belong in the rebuild plan or roadmap; implemented
behaviour belongs in the relevant application README and architecture guide.
